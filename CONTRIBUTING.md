# Contributing to Fluzo Documentation

Use English for specifications, issues and pull requests. Source code, examples
and user conversations need not be translated.

Edit the canonical root documents. Follow the checks in [README.md](README.md)
and submit a focused PR linked to an issue. Identify the affected PRD sections,
architecture decisions and implementation links. Label proposed behavior as
planned; do not mark requirements as implemented without evidence.

Scope, security guarantees, defaults and acceptance changes require explicit
product-owner review and a recorded specification revision. Implementation
details within accepted scope may be refined without inventing new features.

Report runtime bugs in [fluzo](https://github.com/fluzo-labs/fluzo/issues) and
documentation problems in [fluzo-docs](https://github.com/fluzo-labs/fluzo-docs/issues).
Do not include credentials, private server addresses, conversations or
`.fluzodrive/` content. Use [SECURITY.md](SECURITY.md) for vulnerabilities.

For now Jose Corral (`jmanuelcorral`) maintains both repositories. Required checks
and a recorded self-review are feasible for a solo maintainer; independent peer
review should be introduced when another maintainer is available. Contributions
are accepted under the repository's MIT license without claiming to relicense
third-party material.
